# Overlay API 0.2 migration

0.2는 정식 버전 이전의 definition·update·group 중심 API를 제거하고 modal interaction만을 위한
작은 LIFO stack 계약으로 전환한다. 호환 shim은 제공하지 않는다.

## 제거와 대체

| 이전 API | 새 경로 |
| --- | --- |
| `defineOverlay()`, definition input | 일반 React component와 JSX props |
| `overlay.dialog()` | `overlay.open(<Component />)` |
| `overlay.openOrUpdate()`, `handle.update()` | 컴포넌트 내부 state 또는 ID 기반 store/query |
| `dismiss()`, `dismissAll()` | `close()`, `closeAll()` |
| `requestDismiss()`, `completeExit()` | `requestClose()`, `completeClose()` |
| FIFO queue | LIFO stack |
| group, parallel runtime, dedupe, identity lookup | 제거 |
| Core·CLI Toast 통합 | 앱의 별도 notification 시스템 |

## Scope와 Provider

전역 request 타입과 Hook 대신 앱 scope를 만든다.

```tsx
const appOverlay = createOverlayScope<{
  alert: AppAlertRequest
  confirm: AppConfirmRequest
}>()

const renderers = {
  alert: AlertSurface,
  confirm: ConfirmSurface,
} satisfies OverlayRenderers<AppOverlayRequests>
```

호출부는 `appOverlay.useOverlay`, React 밖에서는 `appOverlay.createClient()`를 사용한다.

## Custom overlay

```diff
- const editor = defineOverlay(Editor)
- const outcome = await overlay.open(editor, { projectId })
+ const outcome = await overlay.open<Result>(
+   <Editor projectId={projectId} />,
+ )
```

컴포넌트 안에서 `useOverlaySession<Result>()`을 사용한다.

```diff
- session.dismiss('cancel')
- session.requestDismiss('outside')
- session.completeExit()
+ session.close('cancel')
+ session.requestClose('outside')
+ session.completeClose()
```

`OverlayOutcome`의 종료 branch도 바뀐다.

```diff
- { status: 'dismissed', reason }
+ { status: 'closed', reason }
```

## Props update 제거

`open()`에 전달한 JSX와 props는 호출 시점 snapshot이다. 폼, step, loading처럼 변하는 값은 열린
컴포넌트 내부에서 관리한다. 외부 데이터의 최신 상태가 필요하면 `projectId` 같은 안정적인 ID를
props로 전달하고 store나 query를 구독한다.

## Close 대상

- `overlay.close()`: 현재 client의 topmost 세션
- `handle.close()`: Handle이 가리키는 정확한 세션
- `overlay.closeAll()`: 현재 client의 모든 세션

세션은 closing이 된 뒤에도 Renderer의 `completeClose()`가 호출될 때까지 mount를 유지한다.

## Alert와 Confirm

Alert 표시 필드와 Confirm 표시 필드는 앱이 scope에서 정의한다. Core는 Alert의 동기
`onAction`, Confirm의 동기·비동기 `onConfirm`과 close options만 예약한다. Confirm Renderer는
`actionStatus`와 `error`로 pending·실패·재시도를 표현한다.

## Toast

Toast는 focus를 가두는 modal session과 다른 timeout, swipe, live region, 동시 표시 정책을
필요로 한다. 0.2 Core와 CLI에서는 Toast adapter와 parallel group을 제거한다. 앱의 기존 Toast
라이브러리 또는 별도 notification 계층으로 옮긴다.

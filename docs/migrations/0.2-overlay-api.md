# Overlay API 0.2 migration

이 문서는 정식 버전 이전의 definition·update·group API에서 0.2 modal stack으로 옮길 때 필요한
차이만 기록한다. 현재 API의 전체 사용법과 기본값은 [문서 앱](https://seunjin.github.io/lyrd/)을
기준으로 한다. 호환 shim은 제공하지 않는다.

## 제거와 대체

| 이전 API | 0.2 이후 경로 |
| --- | --- |
| `defineOverlay()`, definition input | 일반 React component와 JSX props |
| `overlay.dialog()` | `overlay.open(<Component />)` |
| `overlay.openOrUpdate()`, `handle.update()` | 컴포넌트 내부 state 또는 ID 기반 store/query |
| `dismiss()`, `dismissAll()` | `close()`, `closeAll()` |
| `requestDismiss()`, `completeExit()` | `requestClose()`, `completeClose()` |
| FIFO queue | LIFO stack |
| group, parallel runtime, dedupe, identity lookup | 제거 |
| Core·CLI Toast 통합 | 앱의 별도 notification 시스템 |

## 전환할 때 주의할 점

- `open()`은 JSX와 props를 호출 시점 snapshot으로 보관한다. 열린 UI의 draft와 loading은
  컴포넌트가 소유하고, 외부 최신값은 안정적인 ID로 query나 store를 구독한다.
- Custom overlay 결과는 `{ status: 'resolved', value }` 또는 `{ status: 'closed', reason }`이다.
- 닫힘을 결정한 뒤에도 Renderer는 exit가 끝날 때 `completeClose()`를 호출해야 한다.
- Alert·Confirm 표시 필드는 앱 scope가 정의한다. Core 예약 behavior는 Alert의 `onAction`,
  Confirm의 `onConfirm`과 close options다.
- Toast는 modal stack과 분리된 앱 notification 시스템으로 이동한다.
